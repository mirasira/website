Understanding Hash Functions

A hash function is a mathematical algorithm that takes data of any size and converts it into a fixed-size output. To understand how they work, let's look at a very simple, hand-calculable algorithm we will call the Positional Prime Hash.

The Algorithm

  1. Assign a number to each letter (A=1, B=2 ... Z=26).
  2. Multiply each letter's value by its position in the word (1st letter x 1, 2nd x 2, etc.).
  3. Sum all the values.
  4. Divide the sum by 11 and take the remainder (modulo 11). This is our hash!

Encoding Words into Hashes

Example 1: "CAT"

  • C (3 x 1) = 3
  • A (1 x 2) = 2
  • T (20 x 3) = 60
  • Sum: 65
  • Hash: 65 % 11 = 10

Example 2: "ACT" (The Avalanche Effect)

Even though it uses the exact same letters, changing the order changes the output completely.

  • A (1 x 1) = 1
  • C (3 x 2) = 6
  • T (20 x 3) = 60
  • Sum: 67
  • Hash: 67 % 11 = 1

The Problem: Hash Collisions

Because our toy function divides by 11 to find the remainder, there are only 11 possible outputs (0 through 10). When millions of different words are squeezed into only 11 possible hashes, you inevitably get two different words that produce the exact same hash. This is called a Hash Collision.

Collision Demonstration

Let's look at the words CAB and DOG:

  • CAB: C(3x1=3) + A(1x2=2) + B(2x3=6). Sum = 11. Hash (11 % 11) = 0.
  • DOG: D(4x1=4) + O(15x2=30) + G(7x3=21). Sum = 55. Hash (55 % 11) = 0.

Both "CAB" and "DOG" result in a hash of 0. In a real security system, a collision means someone could use the wrong password to log into your account!

Real Hash Functions vs. Our Toy

Modern cryptographic hash functions, like SHA-256, work on similar principles of multiplication, addition, and modular arithmetic, but on a massive scale using binary data.

  • Output Size: Our toy outputs 11 possible numbers. SHA-256 outputs a 256-bit number, which means there are 2256 possible hashes. That number is roughly equal to the number of atoms in the visible universe!
  • Collision Probability: Because the pool of possible hashes is so astronomically large, the probability of finding two different files or passwords that share the same SHA-256 hash is practically zero.
